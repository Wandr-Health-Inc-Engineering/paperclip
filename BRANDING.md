# tethr branding

This fork is reskinned as **tethr** (Wandr Health's internal cloud OS). The original project is **paperclip** (paperclipai/paperclip), and we sync from it regularly.

The reskin is designed to absorb upstream changes with minimal friction. The rules below exist to keep merges clean.

## Architecture

| Layer | File | Purpose |
|---|---|---|
| Brand constants | [ui/src/lib/brand.ts](ui/src/lib/brand.ts) | `APP_NAME`, `APP_NAME_FORMAL` — used wherever the user-visible product name appears |
| Theme overrides | [ui/src/styles/tethr-theme.css](ui/src/styles/tethr-theme.css) | CSS variable overrides, font imports, slot-targeted component polish, imported AFTER `index.css` in `main.tsx` |
| Favicons | `ui/public/favicon.*`, `apple-touch-icon.png`, `android-chrome-*.png` | Placeholder T-mark generated by [scripts/generate-tethr-placeholder-favicons.mjs](scripts/generate-tethr-placeholder-favicons.mjs) |
| Wordmark | [ui/src/components/TethrWordmark.tsx](ui/src/components/TethrWordmark.tsx) | In-app wordmark component (Urbanist 800, -0.04em tracking) |
| Theme toggle | Sidebar top bar + [ui/src/components/SidebarAccountMenu.tsx](ui/src/components/SidebarAccountMenu.tsx) | Light/dark toggle wired through the pre-existing `useTheme()` context |

## Voice rules

- Product name is **lowercase "tethr"** everywhere in UI copy, headlines, and toasts.
- Formal capitalized **"Tethr"** is reserved for bios, signatures, and document titles (the breadcrumb builder uses `APP_NAME_FORMAL`).
- Lowercase headlines are intentional and on-brand.

## Override-don't-edit rule

We do NOT edit upstream files when an override layer can do the job:

- **Colors, fonts, borders, radius, component polish** → override CSS variables and slot selectors in `tethr-theme.css`. Never edit `ui/src/index.css` or `ui/src/components/ui/*`.
- **Visible product name in code generated by us** → import `APP_NAME` / `APP_NAME_FORMAL` from `@/lib/brand` when interpolating. Inline `"tethr"` is acceptable for one-off copy that is unlikely to move.
- **shadcn components** → don't touch `ui/src/components/ui/*`. Carry brand via CSS variables and `[data-slot="..."]` selectors from outside.

## What we DON'T rename

These are intentionally left as "paperclip":

- Package names (`@paperclipai/*` workspace packages)
- LocalStorage keys (e.g. `paperclip.theme`) — changing these would reset user preferences across the team
- Error class names, internal IDs, log labels, telemetry events
- The lucide `Paperclip` icon (it's an attachment icon, not branding)
- Server-side HTML comment markers (`<!-- PAPERCLIP_FAVICON_START -->`) — they're contracts the server's `ui-branding.ts` injector reads
- CSS class names with the `paperclip-` prefix (e.g. `paperclip-mdxeditor`, `paperclip-markdown`) — they're scoped selectors used by upstream styles; renaming would break those styles
- **Cross-system string constants** that the frontend compares against backend-produced text. Specifically: `SUCCESSFUL_RUN_HANDOFF_REQUIRED_NOTICE_BODY` and `SUCCESSFUL_RUN_HANDOFF_EXHAUSTED_NOTICE_BODY` in [ui/src/lib/successful-run-handoff.ts](ui/src/lib/successful-run-handoff.ts). The backend (`server/src/services/recovery/`) emits the same literal text; rebranding requires a coordinated server change. Same applies to the `/^Paperclip exhausted/i` regex check.
- **Plugin SDK runtime error** in `packages/plugins/sdk/src/ui/runtime.ts` — it builds the "Paperclip plugin UI runtime is not initialized" message that surfaces in [ui/src/plugins/slots.tsx](ui/src/plugins/slots.tsx) and [ui/src/plugins/bridge.test.ts](ui/src/plugins/bridge.test.ts). Rebranding requires editing the SDK package, which is upstream-tracked and would conflict on merges. Left as-is.
- [ui/src/pages/CompanyExport.tsx](ui/src/pages/CompanyExport.tsx) export-markdown footer links — those credit the origin tool (paperclip.ing) and are part of the exported artifact's audit trail.
- Test/dev fixture data: company name fixtures using `"Paperclip"`, sample project mentions like `"Paperclip App"`, `runTranscriptFixtures.ts` synthetic transcripts. They're fictional data, not product references.

## Post-upstream-merge checklist

After `git merge upstream/master` (or equivalent), run this sweep:

```bash
# 1. New user-visible "Paperclip" strings (exclude known-safe patterns)
grep -rn "Paperclip" ui/src --include='*.tsx' --include='*.ts' \
  | grep -v "@paperclipai" \
  | grep -v "lucide-react" \
  | grep -v "PaperclipSprite\|PAPERCLIP_SPRITES" \
  | grep -v "usePaperclipIssueRuntime\|PaperclipIssueRuntime\|MissingPaperclipSdkUiComponent" \
  | grep -v "isPaperclipManaged\|paperclip_managed\|filterPaperclipYaml" \
  | grep -v "paperclip-mdxeditor\|paperclip-markdown\|paperclip-mention\|paperclip-edit\|paperclip-project\|paperclip-mermaid\|paperclip-issue\|paperclip-edit-in-place"

# 2. New favicon references in index.html (might overwrite our placeholder)
git diff <previous-tethr-head>..HEAD -- ui/index.html ui/public/favicon* ui/public/apple-touch-icon.png ui/public/android-chrome-*

# 3. New CSS variables in index.css that might need brand mapping
git diff <previous-tethr-head>..HEAD -- ui/src/index.css | grep -E '^\+\s*--'

# 4. New chart/destructive color uses we may want to clamp
grep -rn "var(--chart-" ui/src --include='*.tsx' --include='*.css' | wc -l

# 5. Confirm tethr-theme.css still loads after index.css
grep -n "tethr-theme.css" ui/src/main.tsx
```

If a sweep turns up new user-visible Paperclip strings, add them to a brand sweep commit. If new CSS variables show up, decide whether to override them in `tethr-theme.css`. If the favicon block got overwritten, regenerate via `node scripts/generate-tethr-placeholder-favicons.mjs`.

## Regenerating placeholder favicons

```bash
node scripts/generate-tethr-placeholder-favicons.mjs
```

The script writes `favicon-16x16.png`, `favicon-32x32.png`, `apple-touch-icon.png`, `android-chrome-192x192.png`, `android-chrome-512x512.png`, and `favicon.ico` into `ui/public/`. Pure Node — no native deps. Replace with designed assets when a real logo is ready.
